## 2. 实验目标

1. 能说明「到点精度」由两处共同决定：`general_goal_checker` 的容差是导航成功判定的唯一依据，TEB 自带容差每周期被它覆盖。
2. 修改后 `ros2 param get /controller_server general_goal_checker.xy_goal_tolerance` 回读 `0.05`，`yaw_goal_tolerance` 回读 `0.1`。
3. 5 个停靠位各下发一次目标，`/amcl_pose` 与目标点偏差 ≤ 0.05 m 的比例 ≥ 90%。
4. 停靠末段 0.5 m 内 `/cmd_vel` 线速度峰值 ≤ 0.1 m/s。
5. 连续 50 次停靠中，「到位后又启动」的次数 ≤ 2。

## 5. 实施步骤

### 步骤 1：贴标并采集静态停位基线

- **操作说明**：在 5 个停靠位地面贴十字标，用 RViz `Publish Point` 读取各点在 `map` 下坐标；保持 `xy_goal_tolerance: 0.1` 跑 5 次停靠，卷尺量车体基准点偏差。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && ros2 param get /controller_server general_goal_checker.xy_goal_tolerance
```

- **预期输出示例**：`Double value is: 0.1`；基线停位偏差 8~12 cm（与场景背景一致）。
- **完成标志**：5 个点位各 3 次测量取均值，全部写入 `停靠精度测试表.csv`。

### 步骤 2：收紧目标容差

- **操作说明**：编辑 `src/yhs_nav2/param/yhs_nav2.yaml`，定位 `controller_server:` → `general_goal_checker:`（基线第 123~127 行），按 6.1 节整块替换。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && sed -n '123,127p' src/yhs_nav2/param/yhs_nav2.yaml
```

- **预期输出示例**：`general_goal_checker:`、`stateful: True`、`plugin: "nav2_controller::SimpleGoalChecker"`、`xy_goal_tolerance: 0.05`、`yaw_goal_tolerance: 0.1`。
- **完成标志**：`general_goal_checker` 为 4 空格缩进，其下参数为 6 空格。

### 步骤 3：核对 TEB 容差为何保持 0.1

- **操作说明**：只读查看 `FollowPath` 段的两个容差，确认不修改的原因。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && sed -n '159,161p' src/yhs_nav2/param/yhs_nav2.yaml
```

- **预期输出示例**：`      xy_goal_tolerance: 0.1` 与 `      yaw_goal_tolerance: 0.1`。
- **完成标志**：能说明 TEB 每次计算速度都会用目标检查器的 `position.x` 覆盖自身 `goal_tolerance.xy_goal_tolerance`，因此改这里是无效操作。

### 步骤 4：停靠专项接近限速

- **操作说明**：把 `velocity_smoother` 线速度上限临时降到 0.1 以满足「接近速度 ≤ 0.1 m/s」；若未做 S1-01，先补该段。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && grep -n "max_velocity\|min_velocity" src/yhs_nav2/param/yhs_nav2.yaml
```

- **预期输出示例**：`max_velocity: [0.1, 0.0, 0.3]`、`min_velocity: [-0.1, 0.0, -0.3]`。
- **完成标志**：测试结束后必须恢复为 `[0.2, 0.0, 0.3]` / `[-0.2, 0.0, -0.3]`，并在记录表注明为临时值。

### 步骤 5：空载连续停靠 20 次 + 负载复测

- **操作说明**：5 个点位各下发 4 次目标，逐次量测偏差并记录是否「到位又启动」；随后按额定载重对偏差最大的 2 个点位各停靠 5 次。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{pose: {header: {frame_id: map}, pose: {position: {x: 2.0, y: 0.0, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}}" --feedback
ros2 topic echo /amcl_pose --field pose.pose.position --once
```

- **预期输出示例**：`Goal accepted` → `distance_remaining` 递减 → `Goal finished with status: SUCCEEDED`。
- **完成标志**：20 次全部 `SUCCEEDED`，90% 以上偏差 ≤ 0.05 m；负载相对空载偏差增量 ≤ 0.02 m。

## 6. 关键配置与代码

文件路径：`~/ros2_ws/src/yhs_nav2/param/yhs_nav2.yaml`

### 6.1 改动点 A：目标容差

替换位置：基线第 123~127 行（`controller_server` → `ros__parameters` → `general_goal_checker`），整块替换。

```yaml
    general_goal_checker:
      stateful: True
      plugin: "nav2_controller::SimpleGoalChecker"
      xy_goal_tolerance: 0.05
      yaw_goal_tolerance: 0.1
```

| 参数 | 原值 | 新值 | 含义与影响 |
|---|---|---|---|
| `xy_goal_tolerance` | 0.1 | 0.05 | 位置容差，决定「到点」判定门槛；TEB 也读取它作为内部目标容差 |
| `yaw_goal_tolerance` | 0.1 | 0.1（保持） | 约 5.7°，已满足月台需求；再收紧会导致反复原地纠偏 |
| `stateful` | True | True（保持） | 进入容差即锁定，不再因定位抖动退出，是「不来回微调」的关键开关 |

### 6.2 改动点 B：停靠专项接近限速（`velocity_smoother` 段，S1-01 已新增）

```yaml
    max_velocity: [0.1, 0.0, 0.3]
    min_velocity: [-0.1, 0.0, -0.3]
```

| 参数 | 原值（S1-01 后） | 停靠专项值 | 含义与影响 |
|---|---|---|---|
| `max_velocity[0]` | 0.2 | 0.1 | 线速度上限 0.1 m/s，满足「停靠接近速度 ≤ 0.1 m/s」 |
| `max_velocity[2]` | 0.3 | 0.3 | 角速度上限不变，末段仍需调整姿态 |
| `min_velocity` | `[-0.2, 0.0, -0.3]` | `[-0.1, 0.0, -0.3]` | 倒车上限同步，避免后退对位超速 |

> 该组为**停靠专项临时值**，测试完毕必须回到 0.2 档，否则全车运营速度被永久限制在 0.1 m/s。

### 6.3 刻意不改的部分

- `FollowPath.xy_goal_tolerance` / `yaw_goal_tolerance` 保持 0.1：前者每周期被目标检查器覆盖，改它不产生影响，只会造成「以为改了」的误判。
- `progress_checker`（`required_movement_radius: 0.5`、`movement_time_allowance: 10.0`）保持原值：末段 0.3 m 以 0.1 m/s 走完约 3 s，远小于 10 s 超时窗口。

### 10.2 常见问题

| 报错文本 / 现象 | 原因 | 处理步骤 |
|---|---|---|
| `Parameter not set`（`general_goal_checker.xy_goal_tolerance`） | `goal_checker_plugins` 未含该名，或节点未 `active` | 确认 `goal_checker_plugins: ["general_goal_checker"]` 与段名严格一致；`ros2 lifecycle get /controller_server` 应为 `active [3]` |
| `Goal finished with status: ABORTED` | 规划失败、代价图被堵，或容差小于定位抖动 | RViz 看路径是否生成；临时把容差放回 0.08 复测，区分「参数过紧」与「不可达」 |
| `Failed to obtain robot pose` | TF 断链或 AMCL 未发布 `map→odom` | `ros2 run tf2_ros tf2_echo map base_link`；`ros2 lifecycle get /amcl` |
| `Invalid path, Path is empty.` | 全局规划未产出路径 | 目标点可能落在未知区（`allow_unknown: false`），换可达目标复测 |
| 到位后车体来回点动 | `stateful` 被写成 `False`，或接近限速未生效 | 回读 `stateful` 为 `True`；`ros2 param get /velocity_smoother max_velocity` 确认临时值 |
| 停靠整体偏左/偏右且稳定 | 地图与实景偏差或雷达安装角偏差 | 先复核地图与激光重合度，再考虑 S1-10 的雷达预处理，不要用容差掩盖系统偏差 |
| 停车位置随次数漂移 | 打滑或轮径系数不准 | 记录 `/odom` 与卷尺位移比，偏差 > 3% 时先处理底盘标定 |
