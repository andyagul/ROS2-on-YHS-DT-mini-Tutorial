## 二、实验目标

1. 证明当前 YAML 中的恢复参数**没有生效**：段名 `recoveries_server` 与启动节点 `behavior_server` 不一致，插件名 `nav2_recoveries/...` 在 Humble 已不存在。
2. 完成段名与插件名修正，使 `spin/backup/wait` 三类恢复行为按参数执行。
3. 人为堵路时观测到完整动作序列：原地旋转约 90°（`spin_dist="1.57"`）→ 后退 0.30 m（`backup_speed="0.05"`）→ 等待 5 s → 重新规划。
4. 连续 5 次堵路脱困 ≥ 4 次，恢复动作速度不超场景限值，并形成《配置差异清单》与回滚步骤。

## 五、实施步骤

**步骤 1：核对段名与插件名，确认参数失效**

```bash
grep -n -A4 "recoveries_server" src/yhs_nav2/param/yhs_nav2.yaml
```

预期：`401:recoveries_server:`、`402:  ros__parameters:`、`403:    costmap_topic: local_costmap/costmap_raw` …

启动整栈后让节点自报实际值（**关键证据**：段名不匹配时该段完全不被注入）：

```bash
ros2 launch yhs_nav2 yhs_nav2.launch.py
```

另开终端：

```bash
ros2 param get /behavior_server max_rotational_vel
ros2 param get /behavior_server behavior_plugins
```

预期（修正前均为代码默认值，与 YAML 写的 `1.0`/三个插件不同）：

```
Double value is: 1.0
String[] value is: ['spin', 'backup', 'drive_on_heading', 'wait']
```

完成标志：《配置差异清单》列出 3 类问题——段名、插件包名、参数键名（见第六节）。

**步骤 2：替换为 `behavior_server:` 段**

```bash
cd ~/"ROS2 on YHS DT-mini Tutorial"
nano src/yhs_nav2/param/yhs_nav2.yaml
```

把整个 `recoveries_server:` 段替换为第六节给出的 `behavior_server:` 段，段名必须与 `navigation_launch.py` 的 `name='behavior_server'` 完全一致。

完成标志：`grep -n "behavior_server\|nav2_recoveries\|recoveries_server" src/yhs_nav2/param/yhs_nav2.yaml` 只剩 `behavior_server:`，不再出现 `nav2_recoveries`、`recoveries_server`。

**步骤 3：编译、重启、回读**

```bash
cd ~/"ROS2 on YHS DT-mini Tutorial"
colcon build --symlink-install --packages-select yhs_nav2
source install/setup.bash
```

重启整栈后回读（预期依次为 `['spin', 'backup', 'wait']`、`0.3`、`0.1`、`nav2_behaviors/Spin`、`nav2_behaviors/BackUp`、`nav2_behaviors/Wait`）：

```bash
ros2 param get /behavior_server behavior_plugins
ros2 param get /behavior_server max_rotational_vel
ros2 param get /behavior_server min_rotational_vel
ros2 param get /behavior_server spin.plugin
ros2 param get /behavior_server backup.plugin
ros2 param get /behavior_server wait.plugin
ros2 action list | grep -E "spin|backup|wait"
```

预期 action：`/spin`、`/backup`、`/wait`。完成标志：6 个参数回读一致 + 3 个 action 可见。

**步骤 4：人为堵路触发恢复并计时**

在车头正前方 0.6~0.8 m 放箱体，在 RViz 用 `2D Goal Pose` 给一个**越过箱体**的目标（或直接把目标下在箱体正后方），观察轮子动作与日志：

```bash
ros2 topic echo /cmd_vel
```

预期：旋转阶段线性速度 0、角速度峰值 ≈ 0.298 rad/s（符合 `max_rotational_vel: 0.3`）。

```bash
ros2 topic echo /behavior_tree_log --field event_log
```

预期节点序列：`FollowPath` FAILURE → `ClearLocalCostmap-Subtree` → `Spin` RUNNING/SUCCESS → `BackUp` → `Wait`。`behavior_server` 侧日志：`[behavior_server]: Running Spin` / `Spin completed successfully`。

完成标志：一次堵路内同时观测到旋转约 90° + 后退约 0.30 m（0.05 m/s）+ 等待 5 s，总耗时 ≤ 30 s。

**步骤 5：连续 5 次堵路统计**

```bash
for i in 1 2 3 4 5; do echo "第 $i 次：$(date +%T)"; read -p "脱困后回车继续"; done
```

每次把箱体换到新位置（左、右、正前各 1 次，重贴 2 次），记录是否脱困、动作耗时、是否触发安全停车。完成标志：脱困 ≥ 4 次，无节点崩溃，恢复次数上限（行为树 `number_of_retries="6"`）生效。

## 六、关键配置与代码

文件：`src/yhs_nav2/param/yhs_nav2.yaml`；位置：删除原 `recoveries_server:` 段（约 401~420 行），在同一位置（`planner_server_rclcpp_node` 之后、`robot_state_publisher` 之前）写入下面的 `behavior_server:` 段。

| 项 | 原值 → 新值 | 含义 |
|---|---|---|
| 段名 | `recoveries_server:` → `behavior_server:` | 必须等于 launch 中 `Node(name='behavior_server')`，否则整段参数不注入 |
| 插件列表键 | `recovery_plugins:` → `behavior_plugins:` | 1.1.5 的 `behavior_server.cpp` 只 `declare_parameter("behavior_plugins")` |
| `spin.plugin` | `nav2_recoveries/Spin` → `nav2_behaviors/Spin` | `nav2_recoveries` 在 Humble 已并入 `nav2_behaviors`，旧名加载直接 FATAL |
| `backup.plugin` | `nav2_recoveries/BackUp` → `nav2_behaviors/BackUp` | 同上 |
| `wait.plugin` | `nav2_recoveries/Wait` → `nav2_behaviors/Wait` | 同上 |
| `transform_timeout` | `0.1` → `transform_tolerance: 0.2` | 节点只读 `transform_tolerance`（footprint 订阅的 TF 容忍），旧键不生效 |
| `max_rotational_vel` | 1.0 → 0.3 | 旋转角速度上限，须 ≤ 场景 0.3 rad/s 约定 |
| `min_rotational_vel` | 0.4 → 0.1 | 起步/收尾角速度，避免"甩头" |
| `rotational_acc_lim` | 3.2 → 1.0 | 角加速度限幅，减小轮子打滑 |
| `costmap_topic`/`footprint_topic`/`cycle_frequency`/`global_frame`/`robot_base_frame`/`simulate_ahead_time` | 保持原值 | 分别对应 `local_costmap/costmap_raw`、`local_costmap/published_footprint`、10.0、odom、base_link、2.0 |

```yaml
behavior_server:
  ros__parameters:
    costmap_topic: local_costmap/costmap_raw
    footprint_topic: local_costmap/published_footprint
    cycle_frequency: 10.0
    behavior_plugins: ["spin", "backup", "wait"]
    spin:
      plugin: "nav2_behaviors/Spin"
    backup:
      plugin: "nav2_behaviors/BackUp"
    wait:
      plugin: "nav2_behaviors/Wait"
    global_frame: odom
    robot_base_frame: base_link
    transform_tolerance: 0.2      # 原 transform_timeout: 0.1（键名不生效）
    use_sim_time: False
    simulate_ahead_time: 2.0
    max_rotational_vel: 0.3       # 原 1.0
    min_rotational_vel: 0.1       # 原 0.4
    rotational_acc_lim: 1.0       # 原 3.2
```

两条必须知道的边界（否则会误判"参数没生效"）：

1. **后退距离与速度不在 YAML**，取值来自行为树 `navigate_to_pose_w_replanning_and_recovery.xml` 的 `<BackUp backup_dist="0.30" backup_speed="0.05"/>`；0.05 m/s 已满足"≤ 0.1 m/s"安全约定，本实验不改 XML。
2. **旋转角度也不在 YAML**，同样来自行为树 `<Spin spin_dist="1.57"/>`（≈90°）；YAML 只控制角速度与角加速度。

## 八、运行验证

| 终端 | 角色 | 命令 |
|---|---|---|
| A | 整栈 | `ros2 launch yhs_nav2 yhs_nav2.launch.py` |
| B | 速度指令 | `ros2 topic echo /cmd_vel` |
| C | 行为树节点序列 | `ros2 topic echo /behavior_tree_log --field event_log` |
| D | 参数回读 | `ros2 param get /behavior_server max_rotational_vel` |
| E | RViz 代价地图与目标下发 | `ros2 run rviz2 rviz2` |

顺序：① CAN 起网 → ② 终端 A 启动 → ③ 等 `Managed nodes are active` → ④ 终端 D 回读 6 个参数 → ⑤ RViz 给初始位姿 → ⑥ 放障碍并下发目标。

判定标准：① `behavior_plugins` 为 `['spin','backup','wait']`，三个 `<id>.plugin` 均为 `nav2_behaviors/...`；② 堵路后 30 s 内完成 1 次旋转 + 1 次后退并重规划；③ `/cmd_vel` 角速度峰值 ≤ 0.35 rad/s、线速度绝对值 ≤ 0.1 m/s；④ 5 次堵路脱困 ≥ 4 次，`behavior_server` 无崩溃、无 `Failed to change state`；⑤ 后方 0.5 m 有障碍时 BackUp 拒绝执行（碰撞检查生效）属正确行为。

## 十、回滚与常见问题

```bash
cd ~/"ROS2 on YHS DT-mini Tutorial"
cp ~/yhs_labs/S1-06/backup/yhs_nav2.yaml.bak src/yhs_nav2/param/yhs_nav2.yaml
colcon build --symlink-install --packages-select yhs_nav2
source install/setup.bash
```

| 现象 | 原因 | 处理 |
|---|---|---|
| `[behavior_server]: Failed to create behavior spin of type nav2_recoveries/Spin` 并退出 | 插件名仍是旧包 | 三个 `<id>.plugin` 全改为 `nav2_behaviors/Spin`、`BackUp`、`Wait` |
| `FATAL ... 'plugin' param not defined for spin` 后退出 | `behavior_plugins` 列表项与 `<id>.plugin` 子项对不上 | 列表项与子项名逐字对应；缺一个即 `exit(-1)` |
| `ros2 param get /behavior_server max_rotational_vel` 仍为 `1.0` | 段名没改（仍是 `recoveries_server`），或没重启整栈 | 回到步骤 1 的 grep 检查；确认重启了 launch |
| `ros2 param get /behavior_server recovery_plugins` 报参数不存在 | 键名用了旧写法 | 改为 `behavior_plugins` |
| 恢复触发但轮子不动，日志提示碰撞 / 一直 RUNNING | 车身周围被局部代价地图判碰撞，或 `local_costmap/costmap_raw` 未发布 | `ros2 topic hz /local_costmap/costmap_raw`；清空车身周围；`ros2 service call /local_costmap/clear_entirely_local_costmap nav2_msgs/srv/ClearEntireCostmap "{}"` |
| BackUp 不执行 | 后方 0.5 m 内有障碍，属安全设计 | 清空后方；确认不是配置错误 |
| 旋转角度不是 90° | 角度取自行为树 `spin_dist`，不在 YAML | 需改角度请改 XML（超出本实验范围，记录后评审） |
