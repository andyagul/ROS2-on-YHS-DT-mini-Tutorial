## 2. 实验目标

1. 能**实地确认** `orbbec_camera/launch/` 下真实可用的相机 launch 名称，并说明本仓库为何用 `astra.launch.py`。
2. 取消 `yhs_nav2.launch.py` 中相机与 `pointcloud_to_laserscan` 两处注释后，全栈仍能正常启动。
3. `/scan1` 稳定输出，且与 `/scan` 同场景重合偏差 ≤ 0.1 m。
4. 0.05~2 m 低矮障碍在 `/scan1` 与代价地图中可见，检出率 ≥ 90%。
5. 完成"启用前 / 启用后"对同一低矮障碍的检测与绕行对比记录。

## 6. 关键配置与代码

### 6.1 `yhs_nav2.launch.py`：取消注释（第 23–24 行 + 第 133–146 行）

原值：第 23–24 行两行路径定义被注释；第 133–146 行是两段被整段注释的 `IncludeLaunchDescription`（相机块 + 点云转 scan 块），形如：

```python
    # camera_launch_dir = os.path.join(get_package_share_directory('orbbec_camera'),'launch')
    # pointcloud_to_laserscan_launch_dir = os.path.join(get_package_share_directory('pointcloud_to_laserscan'),'launch')
    #        IncludeLaunchDescription(
    #            PythonLaunchDescriptionSource(os.path.join(camera_launch_dir, 'astra.launch.py')), ...
```

新值（插入位置不变，位于底盘 `IncludeLaunchDescription` 之前）：

```python
    camera_launch_dir = os.path.join(get_package_share_directory('orbbec_camera'),'launch')
    pointcloud_to_laserscan_launch_dir = os.path.join(get_package_share_directory('pointcloud_to_laserscan'),'launch')
    ...
        #深度相机节点            
        IncludeLaunchDescription(
            PythonLaunchDescriptionSource(os.path.join(camera_launch_dir, 'astra.launch.py')),
            launch_arguments={'namespace': namespace,
                              'use_sim_time': use_sim_time,
                              'autostart': autostart,
                              'use_respawn': use_respawn}.items()),
        #深度相机点云转scan节点                      
        IncludeLaunchDescription(
            PythonLaunchDescriptionSource(os.path.join(pointcloud_to_laserscan_launch_dir, 'pointcloud_to_laserscan.launch.py')),
            launch_arguments={'namespace': namespace,
                              'use_sim_time': use_sim_time,
                              'autostart': autostart,
                              'use_respawn': use_respawn}.items()),
```

含义：相机以 `camera` 命名空间启动（`astra.launch.py` 的 `camera_name` 默认 `camera`、`enable_point_cloud` 默认 `true`），点云话题为 `/camera/depth/points`；转换节点把它压成 2D 激光 `/scan1`。

### 6.2 `pointcloud_to_laserscan.launch.py` 参数原值 → 新值

文件：`.../src/pointcloud_to_laserscan/launch/pointcloud_to_laserscan.launch.py`，插入位置：第 20–33 行 `parameters=[{ ... }]`。

| 参数 | 原值 → 新值 | 含义与理由 |
|---|---|---|
| `min_height` | `-0.1` → `-0.30` | 相机在 `base_link` 上方 0.2 m，0.05 m 高障碍在 `camera_link` 下约 `z=-0.15`，原值会裁掉地面级目标 |
| `max_height` | `2.0` → `1.0` | `scan1` 只做近距补盲，1.0 m 以上由单线雷达覆盖，避免重复标记货架上层 |
| `angle_min` | `-1.5708` → `-0.5236` | 相机水平视场有限，`±1.5708` 会在视场外产生 `.inf` 射线；`±30°` 与标称视场（约 58°）匹配，按实测微调 |
| `angle_max` | `1.5708` → `0.5236` | 同上 |
| `range_max` | `1.0` → `3.0` | 只给 1 m 会漏掉 1~2 m 的低矮障碍，按清单要求扩到 3.0 m |
| `transform_tolerance` | `0.01` → `0.1` | 0.01 s 过紧，相机时间戳抖动时报外推错误 |
| `target_frame` / `angle_increment` / `scan_time` / `range_min` / `use_inf` | 不改 | 分别为 `camera_link` / `0.0087` / `0.3333` / `0.05` / `True`，与原设计一致 |

改后完整片段：

```python
        Node(
            package='pointcloud_to_laserscan', executable='pointcloud_to_laserscan_node',
            remappings=[('cloud_in', '/camera/depth/points'),
                        ('scan', '/scan1')],
            parameters=[{
                'target_frame': 'camera_link',
                'transform_tolerance': 0.1,
                'min_height': -0.30,
                'max_height': 1.0,
                'angle_min': -0.5236,
                'angle_max': 0.5236,
                'angle_increment': 0.0087,
                'scan_time': 0.3333,
                'range_min': 0.05,
                'range_max': 3.0,
                'use_inf': True,
                'inf_epsilon': 1.0
            }],
            name='pointcloud_to_laserscan'
        )
```

同文件第 10–15 行的静态外参不改：`arguments=['0.23','0','0.2','0','0','0','1','base_link','camera_link']`。

## 8. 运行验证

| 终端 | 分工 | 命令 |
|---|---|---|
| T1 | 全栈（含相机与 `/scan1`） | `ros2 launch yhs_nav2 yhs_nav2.launch.py use_tf:=true map:=<地图.yaml>` |
| T2 | 数据核验 | `ros2 topic hz /scan1`；`ros2 topic echo /scan1 --once --field ranges` |
| T3 | 代价地图与 TF | `ros2 run tf2_tools view_frames`；RViz 看 `/local_costmap/costmap` |

启动顺序：T1 起栈 → 等 `Activating` 完成 → T2 确认 `/scan1` 有频率 → RViz 叠加 `/scan`、`/scan1` → 最后放低矮障碍。

判定标准：① `/scan1` 频率与相机帧率一致；② 同墙重合偏差 ≤ 0.1 m；③ 低矮障碍在 `/local_costmap/costmap` 中为 `LETHAL` 栅格；④ 0.25 m 前减速或绕行、无接触。

## 9. 验收指标

| 维度 | 量化要求（与实施方案 S1-14 一致） | 说明 |
|---|---|---|

## 10. 回滚与常见问题

```bash
# 回滚，执行目录：工作空间根
cd "$HOME/ros2_ws"
cp ~/yhs_labs/S1-14/backup/yhs_nav2.launch.py src/yhs_nav2/launch/
cp ~/yhs_labs/S1-14/backup/pointcloud_to_laserscan.launch.py src/pointcloud_to_laserscan/launch/
colcon build --symlink-install --packages-select pointcloud_to_laserscan yhs_nav2 && source install/setup.bash
```

| 现象 / 报错 | 原因 | 处理 |
|---|---|---|
| `Message Filter dropping message: frame '...' ... queue is full` | `target_frame` 与点云 frame 间无 TF，或时间戳不齐 | `tf2_echo base_link camera_link` 确认 TF；`transform_tolerance` 放宽到 0.2 |
| `Lookup would require extrapolation into the future` | 时间不同步 / `transform_tolerance` 过小（原 0.01） | 改 0.1；核对设备时钟 |
| 点云正常但 `/scan1` 无数据 | 角度区间与相机实际视场不匹配，全落在视场外 | 先恢复 `±1.5708` 观察，再逐步收窄 |
| `/scan1` 全是 `.inf` | 高度区间把有效点裁掉 | `min_height` 取 `-0.30`，在 `camera_link` 下核对障碍物 z 值 |
| `Failed to open device` / `No device found` | USB 带宽或供电不足、`vendor_id` 不符、相机被占用 | 换 USB3 口；`lsusb` 确认 `2bc5`；关掉其他相机进程 |
| 报错找不到 `astra.launch.py` | 相机包未编译，或型号 launch 名不同 | 回第 3 节 `ls .../orbbec_camera/launch` 用真实文件名替换 |
| TF 树出现两个 `camera_link` 父节点 | 相机自带 TF 与静态外参重复发布 | `view_frames` 定位后留一：改静态外参或关闭相机 `publish_tf` |
