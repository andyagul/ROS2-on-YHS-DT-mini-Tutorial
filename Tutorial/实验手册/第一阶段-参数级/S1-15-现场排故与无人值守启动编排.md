## 2. 实验目标

1. 各用一条命令起"调试档"（独立进程 + `debug` 日志）与"运营档"（容器 + `info` + `respawn`）。
2. 能用 `ros2 lifecycle` 手动把 `/amcl`、`/controller_server` 单独 configure/activate，实现"只重启一个节点"。
3. 能在运营档人为 kill 节点，观察进程被拉起且生命周期恢复。
4. 能说明 `autostart`、`use_composition`、`use_respawn`、`log_level` 在本仓库 launch 中的**真实作用点**（含一处与官方语义不同的实现）。
5. 输出覆盖 5 类常见故障的一页排故流程图。

### 步骤 2：生命周期手动管理（30 min）

调试档（`autostart:=false`，重新执行 `./run_debug.sh`）下节点停在 `unconfigured`，逐个拉起：

```bash
# 终端 T2，执行目录：任意
ros2 lifecycle get /amcl            # 预期：unconfigured [1]
ros2 lifecycle set /amcl configure  # 预期：Transitioning successful
ros2 lifecycle set /amcl activate   # 预期：Transitioning successful
ros2 lifecycle get /amcl            # 预期：active [3]
# 单节点重启演练（只重启控制器）
for s in deactivate cleanup configure activate; do ros2 lifecycle set /controller_server $s; done
```

用生命周期管理器批量恢复（`STARTUP=0 / PAUSE=1 / RESUME=2 / RESET=3 / SHUTDOWN=4`）：

```bash
# 终端 T2，执行目录：任意
ros2 service call /lifecycle_manager_navigation/manage_nodes \
  nav2_msgs/srv/ManageLifecycleNodes "{command: 0}"
ros2 service call /lifecycle_manager_navigation/is_active std_srvs/srv/Trigger "{}"
```

预期输出示例：`nav2_msgs.srv.ManageLifecycleNodes_Response(success=True)`、`std_srvs.srv.Trigger_Response(success=True, message='')`。
完成标志：不停整栈即可把单个节点从 `deactivate` 走回 `active`。

## 6. 关键配置与代码

### 6.1 四个参数的真实声明（`yhs_nav2.launch.py` 第 87–101 行）

```python
    declare_autostart_cmd = DeclareLaunchArgument(
        'autostart', default_value='true',
        description='Automatically startup the nav2 stack')
    declare_use_composition_cmd = DeclareLaunchArgument(
        'use_composition', default_value='True',
        description='Whether to use composed bringup')
    declare_use_respawn_cmd = DeclareLaunchArgument(
        'use_respawn', default_value='False',
        description='Whether to respawn if a node crashes. Applied when composition is disabled.')
    declare_log_level_cmd = DeclareLaunchArgument(
        'log_level', default_value='info',
        description='log level')
```

### 6.2 `use_composition` 的唯一作用点（第 109–117 行）

```python
        Node(
            condition=IfCondition(use_composition),
            name='nav2_container',
            package='rclcpp_components',
            executable='component_container_isolated',
            parameters=[configured_params, {'autostart': autostart}],
            arguments=['--ros-args', '--log-level', log_level],
            remappings=remappings, output='screen'),
```

全文件只有这一个节点带 `IfCondition(use_composition)`。

### 6.3 与官方语义不同的一处实现（必须掌握）

`localization_launch.py`（第 89–108 行）与 `navigation_launch.py`（第 85–163 行）中的 `amcl`、`controller_server` 等**都没有** `IfCondition/UnlessCondition`：

```python
            Node(
                package='nav2_amcl',
                executable='amcl',
                name='amcl',
                respawn=use_respawn,
                respawn_delay=2.0,
                parameters=[configured_params],
                arguments=['--ros-args', '--log-level', log_level]),
```

含义：① `use_composition:=false` 实际只是"不启动空的 `nav2_container`"，导航节点本就是独立进程，逐节点排故能力一直存在；② `respawn=use_respawn` 写在各独立 `Node` 上，本仓库 `use_respawn:=true` **确实生效**（与"仅在禁用组合时生效"的官方注释表述有出入）；③ `log_level` 经 `['--ros-args','--log-level',log_level]` 传给每个节点。

### 6.4 两档参数对照（原值 → 建议值）

| 参数 | 原值 | 调试档 | 运营档 | 作用 |
|---|---|---|---|---|
| `autostart` | `true` | `false` | `true` | `false` 时 `lifecycle_manager` 不自动 configure/activate |
| `use_composition` | `True` | `false` | `true` | 只控制是否启动 `nav2_container` |
| `use_respawn` | `False` | `false` | `true` | 崩溃后 `respawn_delay=2.0` 自动拉起 |
| `log_level` | `info` | `debug` | `info` | `debug` 输出规划/控制内部细节，长跑显著增大日志 |

### 6.5 生命周期管理器服务（真实接口）

`nav2_lifecycle_manager.cpp` 第 62–72 行创建 `/lifecycle_manager_navigation/manage_nodes`（`nav2_msgs/srv/ManageLifecycleNodes`）与 `/lifecycle_manager_navigation/is_active`（`std_srvs/srv/Trigger`）；常量见 `nav2_msgs/srv/ManageLifecycleNodes.srv`。

## 8. 运行验证

| 终端 | 分工 | 命令 |
|---|---|---|
| T1 | 启动栈（两档二选一） | `./run_debug.sh` 或 `./run_ops.sh` |

| 现象 / 报错 | 原因 | 处理 |
|---|---|---|
| `ros2 lifecycle get /amcl` 返回 `Node not found` | 栈未起，或节点名写错 | `ros2 node list` 核对真实节点名 |
| `autostart:=false` 后 RViz 一直无 `/map` | `lifecycle_manager` 不自动 configure，`map_server` 停在 `unconfigured` | `ros2 lifecycle set /map_server configure` 再 `activate` |
| kill 后节点没被拉起 | 用了默认 `use_respawn:=false` | 启动加 `use_respawn:=true`；确认 kill 的是独立进程 |
| 进程起来但 `lifecycle get` 为 `unconfigured` | bond 重连未成功（`bond_timeout` 默认 4.0 s） | `manage_nodes` 发 `{command: 2}`（RESUME），或手动 configure/activate |
| `manage_nodes` 返回 `success: False` | 目标节点不在 `navigation_launch.py` 第 27–33 行的 `lifecycle_nodes` 内 | `ros2 node list` 核对；以该列表为准 |
| 两档同时运行、TF 抖动 | 重复起栈导致 `map→odom` 双发布 | `pkill -f yhs_nav2` 后只保留一档 |
| `debug` 档日志刷屏、磁盘上涨 | `log_level:=debug` 输出内部细节 | 排故完切回 `info` |
