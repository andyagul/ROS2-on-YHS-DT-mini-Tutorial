## 2. 实验目标

1. 能说明限速三级链路：TEB（`FollowPath` 段）→ `velocity_smoother` → 底盘 `cmd_vel`，并指出各级参数所在 YAML 段。
2. 修改后 `ros2 param get` 回读 `FollowPath.max_vel_x`=0.2、`acc_lim_x`=0.15、`acc_lim_theta`=0.15，与设计值一致。
3. 新增 `velocity_smoother` 段后，`ros2 param get /velocity_smoother max_velocity` 回读 `[0.2, 0.0, 0.3]`，节点处于 `active`。
4. 架空与落地两轮测试中 `/cmd_vel` 线速度全程 ≤ 0.2 m/s、角速度 ≤ 0.3 rad/s，无速度阶跃。
5. 2 m 直线启停一次完成，实测耗时 ≥ 10 s（0.2 m/s 对应最短耗时），车轮无明显打滑与点头。

## 6. 关键配置与代码

文件路径：`~/ros2_ws/src/yhs_nav2/param/yhs_nav2.yaml`

### 6.1 改动点 A：TEB 限速与加速度

插入/替换位置：基线第 147~151 行（`FollowPath:` 下 `# Robot` 小节），整段替换。

```yaml
      # Robot    
      max_vel_x: 0.2
      max_vel_theta: 0.3
      acc_lim_x: 0.15
      acc_lim_theta: 0.15
```

| 参数 | 原值 | 新值 | 含义与影响 |
|---|---|---|---|
| `max_vel_x` | 0.5 | 0.2 | 线速度硬上限，混行区「慢就是安全」的兜底值 |
| `max_vel_theta` | 0.3 | 0.3（保持） | 角速度上限已符合园区 ≤ 0.3 rad/s 约定 |
| `acc_lim_x` | 0.3 | 0.15 | 线加速度减半，抑制起步打滑与停车点头 |
| `acc_lim_theta` | 0.3 | 0.15 | 角加速度减半，转弯启停更柔和 |

### 6.2 改动点 B：新增 `velocity_smoother` 顶层段

插入位置：`map_server:` 之前（基线第 335 行前），与 `controller_server` 同为顶层键。

```yaml
velocity_smoother:
  ros__parameters:
    use_sim_time: False
    smoothing_frequency: 20.0
    scale_velocities: False
    feedback: "OPEN_LOOP"
    max_velocity: [0.2, 0.0, 0.3]
    min_velocity: [-0.2, 0.0, -0.3]
    max_accel: [0.15, 0.0, 0.15]
    max_decel: [-0.4, 0.0, -0.4]
    odom_topic: "/odom"
    odom_duration: 0.1
    deadband_velocity: [0.02, 0.0, 0.02]
    velocity_timeout: 1.0
```

| 参数 | 原值（未配置，取节点默认） | 新值 | 含义与影响 |
|---|---|---|---|
| `max_velocity` | `[0.50, 0.0, 2.5]` | `[0.2, 0.0, 0.3]` | `(x, y, θ)` 上限；θ 由 2.5 收到 0.3 是本次关键修正 |
| `min_velocity` | `[-0.50, 0.0, -2.5]` | `[-0.2, 0.0, -0.3]` | 倒车与反转闸门，与上限对称 |
| `max_accel` | `[2.5, 0.0, 3.2]` | `[0.15, 0.0, 0.15]` | 与 TEB 同值，避免两级限幅叠加导致「到不了目标速度」 |
| `max_decel` | `[-2.5, 0.0, -3.2]` | `[-0.4, 0.0, -0.4]` | 由验收「停车 ≤ 0.5 s」反推 `0.2/0.5=0.4`，必须为负 |
| `deadband_velocity` | `[0.0, 0.0, 0.0]` | `[0.02, 0.0, 0.02]` | 小于该值的残余指令归零，抑制停车抖动 |
| `velocity_timeout` | 1.0 | 1.0 | 1 s 无新指令即输出零速（上游崩溃的软件兜底） |

- 链路：`controller_server` 发 `/cmd_vel_nav` → `velocity_smoother` 平滑为 `/cmd_vel` → 底盘订阅 `/cmd_vel`；限速是否生效只能看 `/cmd_vel`。
- 硬件急停不经 `velocity_smoother`，`max_decel` 只约束正常减速与避障减速，不替代硬件急停。

### 10.2 常见问题

| 报错文本 / 现象 | 原因 | 处理步骤 |
|---|---|---|
| `Parameter not set`（`FollowPath.max_vel_x`） | 控制器插件未加载或节点未 `active` | `ros2 lifecycle get /controller_server` 应为 `active [3]`；检查 `controller_plugins: ["FollowPath"]` 与缩进 |
| `Positive values set of deceleration! These should be negative to slow down!` | `max_decel` 写成正数 | 改为 `[-0.4, 0.0, -0.4]` 后重启 launch |
| `Invalid setting of kinematic and/or deadband limits! All limits must be size of 3 representing (x, y, theta).` | 数组元素不是 3 个 | 补为 `[x, y, θ]`，y 分量固定写 `0.0` |
| 车速仍明显超 0.2 m/s | 改的是 `/cmd_vel_nav` 侧，或 smoother 段未加载 | 回读 `/velocity_smoother max_velocity`；`ros2 node list` 中应有 `/velocity_smoother` |
| `下发速度，底盘没响应，请检查遥控器是否切换到指令模式...` | 底盘处于遥控模式或 CAN 未 up | 切到指令模式；`ip -details link show can0` 确认 `state UP` |
| `yaml.scanner.ScannerError` / launch 启动即退 | 冒号后缺空格、Tab 缩进、数组漏逗号 | 用步骤 3 的解析命令定位行号；YAML 只允许空格缩进 |
