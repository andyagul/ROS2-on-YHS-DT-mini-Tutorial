## 2. 实验目标

1. 能按 `ChassisInfoFb` 的六段结构（`ctrl_fb`、`io_fb`、`l_wheel_fb`、`r_wheel_fb`、`bms_fb`、`bms_flag_fb`）逐项读出整车状态并说明单位。
2. 能编写单文件 rclpy 节点，以 0.5 s 周期把底盘反馈渲染成一屏状态，运行后 1 s 内出数据。
3. 能设置电压、SOC、急停、碰撞、跌落阈值，越阈值项 1 s 内红色高亮。
4. 覆盖 ≥ 16 项状态量（电压/电流/SOC/左右轮速/6 路碰撞/6 路跌落/急停），并能在 8 h 运行后核对内存与断流。

## 5. 实施步骤

### 5.1 写入完整脚本

把下面全文写入 `~/yhs_labs/S2-01/chassis_monitor.py`（唯一副本，不再另存）：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""S2-01 整车状态看板：只订阅 /chassis_info_fb，不发布控制指令。"""

from datetime import datetime

import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy
from yhs_can_interfaces.msg import ChassisInfoFb

CLEAR = '\033[2J\033[H'
RED, YEL, GRN, DIM, RST = '\033[31m', '\033[33m', '\033[32m', '\033[90m', '\033[0m'
IMPACT = [('左前', 'io_fb_fl_impact_sensor'), ('前中', 'io_fb_fm_impact_sensor'),
          ('右前', 'io_fb_fr_impact_sensor'), ('左后', 'io_fb_rl_impact_sensor'),
          ('后中', 'io_fb_rm_impact_sensor'), ('右后', 'io_fb_rr_impact_sensor')]
DROP = [(n, f.replace('impact', 'drop')) for n, f in IMPACT]


class ChassisMonitor(Node):
    """把 ChassisInfoFb 渲染成值班员可读的一屏状态。"""

    def __init__(self):
        super().__init__('chassis_monitor_s2_01')
        params = (('topic', '/chassis_info_fb'), ('refresh_period', 0.5), ('timeout', 1.0),
                  ('voltage_warn', 47.0), ('voltage_min', 45.0), ('soc_warn', 30), ('soc_min', 15))
        for name, value in params:
            self.declare_parameter(name, value)
        self.topic = str(self.get_parameter('topic').value)
        self.timeout = float(self.get_parameter('timeout').value)
        self.v_warn = float(self.get_parameter('voltage_warn').value)
        self.v_min = float(self.get_parameter('voltage_min').value)
        self.soc_warn = int(self.get_parameter('soc_warn').value)
        self.soc_min = int(self.get_parameter('soc_min').value)
        period = float(self.get_parameter('refresh_period').value)
        qos = QoSProfile(depth=10, reliability=ReliabilityPolicy.RELIABLE,
                         history=HistoryPolicy.KEEP_LAST)
        self.sub = self.create_subscription(ChassisInfoFb, self.topic, self.on_chassis, qos)
        self.msg, self.rx_time, self.count = None, None, 0
        self.create_timer(period, self.render)
        self.get_logger().info(f'看板已启动：订阅 {self.topic}，刷新周期 {period:.1f} s')
    def on_chassis(self, msg):
        self.msg, self.rx_time = msg, self.get_clock().now()
        self.count += 1
    @staticmethod
    def bad(active):
        return RED + '[异常]' + RST if active else GRN + '[ 正常 ]' + RST
    @staticmethod
    def good(active):
        return GRN + '[ 正常 ]' + RST if active else YEL + '[ 未生效 ]' + RST
    def render(self):
        if self.msg is None:
            print(CLEAR + YEL + '等待 /chassis_info_fb 数据 ……' + RST, flush=True)
            return
        m = self.msg
        io, bms, bf = m.io_fb, m.bms_fb, m.bms_flag_fb
        age = (self.get_clock().now() - self.rx_time).nanoseconds / 1e9
        v, soc = bms.bms_fb_voltage, int(bf.bms_flag_fb_soc)
        v_color = RED if v <= self.v_min else (YEL if v <= self.v_warn else GRN)
        s_color = RED if soc <= self.soc_min else (YEL if soc <= self.soc_warn else GRN)
        impacts = [n for n, f in IMPACT if getattr(io, f)]
        drops = [n for n, f in DROP if getattr(io, f)]
        if age > self.timeout:
            verdict = RED + '数据断流' + RST
        elif impacts:
            verdict = RED + '碰撞：' + '/'.join(impacts) + RST
        elif drops:
            verdict = RED + '跌落：' + '/'.join(drops) + RST
        elif io.io_fb_estop:
            verdict = RED + '急停被按下' + RST
        elif v <= self.v_min or soc <= self.soc_min:
            verdict = RED + '电源危险' + RST
        elif v <= self.v_warn or soc <= self.soc_warn:
            verdict = YEL + '电源预警' + RST
        else:
            verdict = GRN + '正常' + RST
        print(CLEAR + '\n'.join([
            f'{DIM}============ 整车状态看板  {datetime.now().strftime("%H:%M:%S.%f")[:-3]} ============{RST}',
            f'数据帧 {self.count:>7d} 帧  最新帧延迟 {age:5.2f} s  判定 {verdict}',
            f'电源   {v_color}{v:6.2f} V{RST}  电流 {bms.bms_fb_current:6.2f} A  '
            f'剩余 {bms.bms_fb_remaining_capacity:6.2f} Ah  SOC {s_color}{soc:3d}%{RST}',
            f'控制   档位 {m.ctrl_fb.ctrl_fb_target_gear}  线速度 {m.ctrl_fb.ctrl_fb_linear:5.2f} m/s  '
            f'角速度 {m.ctrl_fb.ctrl_fb_angular:5.2f} deg/s',
            f'轮速   左 {m.l_wheel_fb.l_wheel_fb_velocity:6.3f} m/s  '
            f'右 {m.r_wheel_fb.r_wheel_fb_velocity:6.3f} m/s',
            '碰撞   ' + ' '.join(f'{n}{self.bad(getattr(io, f))}' for n, f in IMPACT),
            '跌落   ' + ' '.join(f'{n}{self.bad(getattr(io, f))}' for n, f in DROP),
            f'安全   急停{self.bad(io.io_fb_estop)} 手柄{self.good(io.io_fb_joypad_ctrl)} '
            f'充电{self.good(io.io_fb_charge_state)} 喇叭{"开" if io.io_fb_speaker else "关"}',
            f'{DIM}阈值：电压 {self.v_warn}/{self.v_min} V，SOC {self.soc_warn}/{self.soc_min} %，'
            f'超时 {self.timeout} s（Ctrl+C 退出）{RST}',
        ]), flush=True)


def main(args=None):
    rclpy.init(args=args)
    node = ChassisMonitor()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        node.get_logger().info(f'收到 Ctrl+C，共接收 {node.count} 帧，看板退出')
    finally:
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### 5.3 触发一次异常并跟车比对

保持车轮架空，由安全员触发一次急停（或遮挡一路跌落开关），另开终端执行 `ros2 topic echo /chassis_info_fb --field io_fb.io_fb_estop`。预期：看板"急停"由绿 `[ 正常 ]` 变红 `[异常]`，判定变"急停被按下"，触发到变色 ≤ 1 s，恢复后自动回到"正常"；遮挡跌落开关时判定显示"跌落：左前"等位置。

随后安全员随车 30 min，记录员每 10 min 记录屏上数值与现场实际（万用表电压、轮子转向、急停状态）≥ 3 条。完成标志：颜色/判定/`--field` 三者一致，连续 5 次无漏报，跟车记录无字段错位。

## 6. 关键代码与配置

完整源码见 5.1 节（全实验只保留一份文件），逐段作用：

| 代码段 | 作用 | 关键点 |
|---|---|---|
| 头部常量 | 清屏、颜色、6 路碰撞/跌落字段对照 | 字段名与 `IoFb.msg` 一致；`DROP` 由 `IMPACT` 替换 `impact→drop` 生成 |
| 参数声明 | 话题名、刷新周期、超时、电压/SOC 阈值 | 7 个参数均可用 `-p` 覆盖 |
| `QoSProfile` + 订阅 | 订阅 `/chassis_info_fb` | 底盘 publisher 为 RELIABLE/KEEP_LAST(1)，订阅 depth 10 兼容 |
| `on_chassis` | 缓存最新帧与接收时刻 | 高频回调只赋值，不做耗时操作 |
| `render` | 0.5 s 渲染一屏并判定阈值 | `flush=True` 保证重定向到文件时实时刷新 |
| `main` | init / spin / Ctrl+C 退出 | `finally` 中 `destroy_node` + `shutdown` |

| 话题 | 类型 | 方向 | QoS（实车） |
|---|---|---|---|
| `/chassis_info_fb` | `yhs_can_interfaces/msg/ChassisInfoFb` | 订阅 | RELIABLE，KEEP_LAST，depth 1 |
| `/io_cmd` | `yhs_can_interfaces/msg/IoCmd` | 不涉及 | 由底盘节点 depth 1 订阅 |

| 字段 | 单位/取值 | 正常范围 | 告警 |
|---|---|---|---|
| `bms_fb.bms_fb_voltage` | V | 48 V 包 ≥ 47.0 V | ≤ 47.0 预警，≤ 45.0 危险 |
| `bms_fb.bms_fb_current` | A（放电为正） | 随负载 | 仅显示 |
| `bms_fb.bms_fb_remaining_capacity` | Ah | 随容量 | 仅显示 |
| `bms_flag_fb.bms_flag_fb_soc` | %（uint8） | ≥ 30 | ≤ 30 预警，≤ 15 危险 |
| `l/r_wheel_fb_velocity` | m/s | 与 `ctrl_fb_linear` 接近 | 偏差 > 0.05 人工复核 |
| `io_fb.io_fb_*_impact_sensor` | bool，true=碰撞 | 全 false | 任一 true 判"碰撞" |
| `io_fb.io_fb_*_drop_sensor` | bool，true=跌落 | 全 false | 任一 true 判"跌落" |
| `io_fb.io_fb_estop` | bool，true=急停按下 | false | true 判"急停" |

> 24 V 平台改为 `-p voltage_warn:=23.0 -p voltage_min:=22.0`。

## 10. 回滚与常见问题

回滚（本实验不改仓库与参数，回滚即"停脚本 + 清目录"）：①脚本终端 `Ctrl+C`，日志出现"看板退出"；②若触发过急停，由安全员按操作卡解除，车辆保持架空；③`rm -rf ~/yhs_labs/S2-01`；④`git status` 应无新增文件。

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: No module named 'rclpy'` | 未 source ROS 2 或用非系统 Python | `source /opt/ros/humble/setup.bash`，用 `/usr/bin/python3` |
| `No module named 'yhs_can_interfaces'` | 未 source 工作空间或未编译 | `source install/setup.bash`；`ros2 pkg prefix yhs_can_interfaces` |
| 一直"等待 /chassis_info_fb 数据" | 底盘未启动、`can0` 未 up、未上电 | `ros2 node list`；`candump can0` |
| 有数据但电压/SOC 恒为 0 | BMS 未上报 | 查电池通信线；判"电源危险"属真实反馈 |
| 终端显示 `\033[31m` 文本 | 终端不支持 ANSI | `export TERM=xterm-256color`，在真实终端运行 |
| 帧数不增长、数据跳变 | 回调被阻塞或队列过小 | 保持 depth 10；回调内不 `print`/写文件 |
