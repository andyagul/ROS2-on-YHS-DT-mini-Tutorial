## 二、实验目标

1. 能在实车上读出 AMCL 六个关键参数的真实生效值，并说明每个参数对定位精度与 CPU 开销的作用方向。
2. 建立可复现的定位基线：5 个参考点位姿复现偏差、直行段最大单步跳变、`amcl` 进程 CPU 占用。
3. 完成调整后同一参考点位姿抖动 ≤ 0.03 m，CPU 相对基线下降 ≥ 20%。
4. 长走廊往返 10 次连续运行无人工接管、无定位丢失，并形成参数变更单与一键回滚步骤。

## 五、实施步骤

**步骤 1：采集基线（位姿 + 跳变 + CPU）**

终端 A 启动整栈：

```bash
ros2 launch yhs_nav2 yhs_nav2.launch.py
```

预期关键行：`[map_server-1] [INFO] [map_io]: Loading yaml file: .../map/ecarroom.yaml` 与 `Managed nodes are active`。

终端 B 设初始位姿（`x/y/theta` 换实际起点，打印后 `Ctrl+C`）：

```bash
ros2 run yhs_nav2 set_init_amcl_pose.py --ros-args -p x:=0.0 -p y:=0.0 -p theta:=0.0
```

预期：`[init_pose_publisher]: Setting initial AMCL pose to [x: 0.0, y: 0.0, theta: 0.0] ...`。

终端 C 在每次停稳前 3 s 启动、停稳后 `Ctrl+C` 取最后一行读数（5 个参考点各一次）；终端 D 记录 AMCL 进程 CPU 取 3 次均值（`amcl` 是独立进程，不在 Nav2 容器内）：

```bash
ros2 topic echo /amcl_pose --field pose.pose.position
top -b -n 1 -p $(pgrep -x amcl) | tail -2
```

预期：位姿读数示例 `x: 3.184` / `y: 0.021` / `z: 0.0`；CPU 示例 `%CPU 38.4`（机型差异大）。

终端 E 采样直行段跳变，同时缓慢直行 4 m，脚本运行 20 s：

```bash
python3 - <<'EOF'
import time, math, rclpy
from rclpy.node import Node
from geometry_msgs.msg import PoseWithCovarianceStamped
pts = []
class Probe(Node):
    def __init__(self):
        super().__init__('pose_probe')
        self.create_subscription(PoseWithCovarianceStamped, '/amcl_pose', self.cb, 10)
    def cb(self, msg):
        p = msg.pose.pose.position
        pts.append((p.x, p.y))
rclpy.init(); node = Probe(); t0 = time.time()
while time.time() - t0 < 20.0:
    rclpy.spin_once(node, timeout_sec=0.1)
node.destroy_node(); rclpy.shutdown()
if len(pts) < 2:
    print('样本不足：静止时 AMCL 不更新，请缓慢直行 2 m 以上重测')
else:
    jumps = [math.hypot(pts[i+1][0]-pts[i][0], pts[i+1][1]-pts[i][1]) for i in range(len(pts)-1)]
    print(f'样本数={len(pts)} 最大单步跳变={max(jumps):.3f} m 平均步长={sum(jumps)/len(jumps):.3f} m')
EOF
```

预期（基线，长走廊激光退化时跳变明显）：

```
样本数=41 最大单步跳变=0.214 m 平均步长=0.101 m
```

完成标志：《定位基线表》含 5 个参考点读数、CPU 均值、最大单步跳变共 7 项数据。

## 六、关键配置与代码

文件：`src/yhs_nav2/param/yhs_nav2.yaml`；位置：第 1~45 行 `amcl:` → `ros__parameters:` 段内逐项改值（不新增键、不改段名）。

| 参数 | 原值 → 新值 | 含义与取舍 |
|---|---|---|
| `max_beams` | 48 → 60 | 每次更新的采样光束数。提高后似然场匹配更稳、长走廊抖动更小；计算量上升，需靠粒子数下降抵消 |
| `min_particles` | 500 → 300 | 粒子数下限。慢速/静止时减少无效粒子，降 CPU |
| `max_particles` | 5000 → 2000 | 粒子数上限。压缩最坏情况 CPU 峰值 |
| `update_min_d` | 0.1 → 0.05 | 触发更新的最小平移量。更新更密，抑制"跳一下再修正"的大步跳变 |
| `laser_max_range` | 48.0 → 20.0 | 参与似然计算的最大量程。走廊 20 m 外回波无贡献，截断后每帧计算量明显下降 |
| `transform_tolerance` | 1.0 → 0.3 | `map→odom` 发布前瞻。收紧后定位滞后减小；TF 抖动大时会超时，可回退 0.5 |

`update_min_a` 保持 0.2 不改：旋转与平移阈值同时收紧会让每帧都触发更新，CPU 反而升高。

```yaml
amcl:
  ros__parameters:
    alpha1: 0.1
    alpha2: 0.1
    alpha3: 0.1
    alpha4: 0.1
    alpha5: 0
    base_frame_id: "base_link"
    beam_skip_distance: 0.5
    beam_skip_error_threshold: 0.9
    beam_skip_threshold: 0.3
    do_beamskip: false
    global_frame_id: "map"
    lambda_short: 0.1
    laser_likelihood_max_dist: 2.0
    laser_max_range: 20.0          # 原 48.0
    laser_min_range: 0.5
    laser_model_type: "likelihood_field"
    max_beams: 60                  # 原 48
    max_particles: 2000            # 原 5000
    min_particles: 300             # 原 500
    odom_frame_id: "odom"
    pf_err: 0.05
    pf_z: 0.99
    recovery_alpha_fast: 0.0
    recovery_alpha_slow: 0.0
    resample_interval: 1
    robot_model_type: "nav2_amcl::DifferentialMotionModel"
    save_pose_rate: 0.5
    sigma_hit: 0.2
    tf_broadcast: true
    transform_tolerance: 0.3       # 原 1.0
    update_min_a: 0.2
    update_min_d: 0.05             # 原 0.1
    z_hit: 0.5
    z_max: 0.5
    z_rand: 0.5
    z_short: 0.5
    scan_topic: scan
    set_initial_pose: True
    initial_pose:
      x: 0.0
      y: 0.0
      z: 0.0
      yaw: 0.0
```

## 八、运行验证

| 终端 | 角色 | 命令 |
|---|---|---|
| A | 整栈（底盘+雷达+IMU+定位+导航） | `ros2 launch yhs_nav2 yhs_nav2.launch.py` |
| B | 初始位姿 | `ros2 run yhs_nav2 set_init_amcl_pose.py --ros-args -p x:=0.0 -p y:=0.0 -p theta:=0.0` |

| D | RViz 粒子云与地图 | `ros2 run rviz2 rviz2` |

顺序：① CAN 起网 → ② 终端 A 启动 → ③ 等 `Managed nodes are active` → ④ 终端 B 给初始位姿 → ⑤ RViz 确认粒子云单峰收敛 → ⑥ 采样。

判定标准：① 6 个参数回读一致；② 同一参考点 5 次停靠读数极差 ≤ 0.03 m、5 点可用率 100%；③ 直行最大单步跳变不大于基线（理想 ≤ 0.06 m）；④ CPU 相对基线降 ≥ 20% 且 ≤ 65%；⑤ 人为重置初始位姿后重定位 ≤ 5 s；⑥ 10 次往返无人工接管。

## 九、验收指标

| 维度 | 量化要求 | 测量方式 |
|---|---|---|
| 功能完整性 | 5 点位姿可用率 ≥ 99%，重定位 ≤ 5 s，静止抖动 ≤ 0.03 m | 5 点各 5 次读数 + 重置初始位姿计时；读数极差 |
| 安全性 | 定位丢失触发停车 ≤ 1 s | 人为断 `/scan`，看 `/cmd_vel` 归零时间 |
| 稳定性 | 连续 2 h 定位误差 ≤ 0.1 m | 往返 10 次对比参考点实测坐标 |
| 稳定性 | CPU ≤ 65%，较基线降 ≥ 20%；10 次往返无接管 | `top -p $(pgrep -x amcl)` 前后各 3 次均值 + 记录表 |

任一项不达标不得进入 S1-06，先按第十节回退单项再复测。

## 十、回滚与常见问题

```bash
cd ~/"ROS2 on YHS DT-mini Tutorial"
cp ~/yhs_labs/S1-05/backup/yhs_nav2.yaml.bak src/yhs_nav2/param/yhs_nav2.yaml
colcon build --symlink-install --packages-select yhs_nav2
source install/setup.bash
```

| 现象 | 原因 | 处理 |
|---|---|---|
| `ros2 param get /amcl max_beams` 仍为 `48` | 未 `source`、launch 传了别的 `params_file`、或 YAML 段名被改 | `ros2 param list /amcl` 确认节点在跑；`grep max_beams install/.../param/yhs_nav2.yaml`；确认启动命令未传 `params_file:=` |
| 刷 `Timed out waiting for transform from base_link to map to become available` | `transform_tolerance` 0.3 过小或 TF 断链 | 先 `ros2 run tf2_ros tf2_echo map base_link`；TF 正常则回退 0.5 |
| 走廊中段"抽一下"、粒子云发散 | 几何重复 + `max_particles` 2000 不足以维持多峰 | `max_particles` 调 3000，`min_particles` 保持 300，复测抖动与 CPU |
| CPU 反比基线高 | `max_beams` 48→60 的增量超过粒子缩减收益 | `max_beams` 回退 48 复测；抖动仍达标则保留并记录取舍 |
| `[amcl]: No laser scan received ...` | `/scan` 断流或 QoS 不匹配 | `ros2 topic hz /scan --qos-reliability best_effort`；重启雷达；确认 `scan_topic: scan` |
| 5 点读数极差 > 0.1 m 且改参无改善 | 地图精度不足或参考点选在玻璃/反光面 | 先按 S1-08 重采地图；参考点改选门框、立柱 |
