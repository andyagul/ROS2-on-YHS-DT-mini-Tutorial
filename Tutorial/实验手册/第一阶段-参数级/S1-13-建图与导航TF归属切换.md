## 2. 实验目标

1. 能写出两种模式的 TF 责任表，指出 `map→odom`、`odom→base_link` 各自唯一的发布者。
2. `use_tf:=false` 建图时，`view_frames` 中 `odom→base_link` 的发布者只有 `cartographer_node`。
3. `use_tf:=true` 导航时，`odom→base_link` 只有 `yhs_can_control_node`，`map→odom` 只有 `amcl`。
4. 仅改 `cfg.yaml` 的 `can_name` 即可切换 CAN 接口，`ros2 param get` 读回与设计一致。
5. 产出两套可复用启动命令模板，切换后首动速度 ≤ 0.1 m/s。

## 5. 实施步骤

### 步骤 1：TF 责任表（10 min）

| TF 边 | 建图档（`use_tf:=false`） | 导航档（`use_tf:=true`） |
|---|---|---|
| `map→odom` | `cartographer_node`（`dgt_mini.lua`：`map_frame="map"`、`provide_odom_frame=true`） | `amcl`（`yhs_nav2.yaml`：`tf_broadcast: true`、`global_frame_id: "map"`） |
| `odom→base_link` | `cartographer_node`（`published_frame="base_link"`） | `yhs_can_control_node`（`yhs_can_control_node.cpp` 第 459 行 `if(use_tf_)`） |
| `base_link→laser_link` | `static_tf_pub_laser`（`nvilidar.launch.py`：`0 0 0.33`） | 同左 |
| `/odom` 数据源 | `yhs_can_control_node`（不受 `use_tf` 影响） | 同左 |

**核心结论**：`use_tf` 只决定"谁广播 `odom→base_link`"，不改变 `/odom` 话题；建图时若底盘也广播，会与 Cartographer 抢同一条边。

## 6. 关键配置与代码

### 6.1 `cfg.yaml`（真实内容仅一项）

路径：`~/ros2_ws/src/yhs_can_control/params/cfg.yaml`，插入位置：全文第 1–3 行。

原值：

```yaml
yhs_can_control_node:
  ros__parameters:
    can_name: "can0"
```

新值（`can0` → 现场接口名）：

```yaml
yhs_can_control_node:
  ros__parameters:
    can_name: "can1"
```

含义：节点用 `READ_PARAM(std::string, "can_name", (if_name_), "can0")` 读取（源码第 9 行），决定打开哪一路 SocketCAN。

### 6.2 `use_tf` 的真实透传链路

`cartographer.launch.py` 第 39 行（建图档默认 `false`）：

```python
    declare_use_tf_cmd = DeclareLaunchArgument('use_tf', default_value='false', description='is use_tf?')
```

第 96–102 行透传给底盘：

```python
        IncludeLaunchDescription(
            PythonLaunchDescriptionSource(os.path.join(chassis_launch_dir, 'yhs_can_control.launch.py')),
            launch_arguments={'namespace': namespace,
                              'use_sim_time': use_sim_time,
                              'autostart': autostart,
                              'use_respawn': use_respawn,
                              'use_tf': use_tf}.items()),
```

`yhs_nav2.launch.py` 第 56–59 行（导航档默认 `true`）：

```python
    declare_use_tf_cmd = DeclareLaunchArgument(
        'use_tf', 
        default_value='true', 
        description='is use_tf?')
```

含义：`true` → 底盘发 `odom→base_link`（AMCL 只管 `map→odom`）；`false` → 底盘不发，Cartographer 依 `dgt_mini.lua` 第 20–25 行（`provide_odom_frame=true`、`published_frame="base_link"`）同时发 `map→odom` 与 `odom→base_link`。

| 终端 | 建图档 | 导航档 |
|---|---|---|

## 10. 回滚与常见问题

```bash
# 回滚，执行目录：工作空间根
cd "$HOME/ros2_ws"
cp ~/yhs_labs/S1-13/backup/cfg.yaml.bak src/yhs_can_control/params/cfg.yaml
colcon build --symlink-install --packages-select yhs_can_control && source install/setup.bash
```

| 现象 / 报错 | 原因 | 处理 |
|---|---|---|
| `view_frames` 出现两条 `odom→base_link`，`tf2_echo` 数值来回跳 | 建图档误用 `use_tf:=true`，底盘与 Cartographer 同时发布 | 建图改为 `use_tf:=false`；`ros2 node list` 确认无残留底盘节点 |
| `Timed out waiting for transform from base_link to map` | 导航档 `use_tf:=false`，`odom→base_link` 无人发布 | 导航启动改 `use_tf:=true` |
| `Lookup would require extrapolation into the future` | 两档同时运行导致 `map→odom` 双发布；或时差 | 只保留一个 launch；确认 `use_sim_time:=false` |
| `param get can_name` 仍为 `can0` | `yhs_can_control.launch.py` 第 29 行 `parameters=[{parameter_file},{'use_tf': use_tf}]` 中 `{parameter_file}` 是集合字面量，`cfg.yaml` 未被加载（见《ROS2小车系统架构分析.md》已知问题 9） | 改成 `parameters=[parameter_file, {'use_tf': use_tf}]`；或先 `ros2 run yhs_can_control yhs_can_control_node --ros-args -p can_name:=can1` 验证接口 |
| `can1` 无报文 | 接口未 up / 波特率不符 / 接在另一路 | `sudo ip link set can1 up type can bitrate 500000`；`ip -details link show can1` 看 ERROR-ACTIVE |
| Cartographer 报 `Failed to compute odom pose` | `provide_odom_frame` 被改为 `false` 且底盘 `use_tf:=false` | 恢复 `dgt_mini.lua` 中 `provide_odom_frame = true` |
