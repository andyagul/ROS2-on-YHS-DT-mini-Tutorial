> 配套：[二次开发场景实施方案.md(../二次开发场景实施方案.md)（S1-07）、[二次开发项目清单.md(../二次开发项目清单.md)（第一阶段 #7）

## 二、实验目标

1. 定位本机真实的行为树目录，列出 ≥ 3 个可用 XML 及其用途与可用性。
2. 说清 `default_bt_xml_filename` 在 Humble 失效的原因，并改为 `default_nav_to_pose_bt_xml`（绝对路径）。
3. 用两套配置在同一目标点上跑出可观测差异，并在 `/behavior_tree_log` 中核对节点序列。
4. 完成 10 次切换：车辆静止、无速度残留、无节点重启，产出《模式切换作业卡》。

## 六、关键配置与代码

文件：`src/yhs_nav2/param/yhs_nav2.yaml`；位置：`bt_navigator:` → `ros__parameters:` 段，替换原第 61 行。

| 项 | 原值 → 新值 | 含义 |
|---|---|---|
| 参数名 | `default_bt_xml_filename` → `default_nav_to_pose_bt_xml` | 前者在 Humble 未被声明，写它等于没写；后者由 `navigate_to_pose.cpp` 的 `getDefaultBTFilepath()` 读取 |
| 参数值 | `"navigate_w_replanning_and_recovery.xml"` → 绝对路径 | 该文件不存在，且相对名不会被解析到包目录 |
| 写法 | 相对文件名 → 含空格的绝对路径（YAML 双引号包裹） | `bt_action_server` 用 `std::ifstream` 直接打开 |
| 模式 A | — → `.../navigate_to_pose_w_replanning_and_recovery.xml` | 2 Hz 重规划 + 清代价地图 + Spin/Wait/BackUp，月台到点即停 |
| 模式 B | — → `.../navigate_w_replanning_distance.xml` | 每 1 m 重规划，贴合巡检持续跟踪 |

模式 A 片段（其余字段 `bt_loop_duration`、`default_server_timeout`、`groot_*`、`plugin_lib_names` 全部保持原样）：

```yaml
bt_navigator:
  ros__parameters:
    use_sim_time: False
    global_frame: map
    robot_base_frame: base_link
    odom_topic: /odom
    # 原: default_bt_xml_filename: "navigate_w_replanning_and_recovery.xml"
    default_nav_to_pose_bt_xml: "$HOME/ros2_ws/install/nav2_bt_navigator/share/nav2_bt_navigator/behavior_trees/navigate_to_pose_w_replanning_and_recovery.xml"
    bt_loop_duration: 50
    default_server_timeout: 20
    enable_groot_monitoring: True
    groot_zmq_publisher_port: 1666
    groot_zmq_server_port: 1667
    plugin_lib_names:
    # ……原有 32 项插件列表保持不变……
```

模式 B 只改一行：

```yaml
    default_nav_to_pose_bt_xml: "$HOME/ros2_ws/install/nav2_bt_navigator/share/nav2_bt_navigator/behavior_trees/navigate_w_replanning_distance.xml"
```

本仓库真实存在的行为树与可用性（核对结论）：

| 文件 | 用途 | 是否可直接用 |
|---|---|---|
| `navigate_to_pose_w_replanning_and_recovery.xml` | 标准：2 Hz 重规划 + 清除代价地图 + Spin/Wait/BackUp 恢复 | 是（模式 A） |
| `navigate_w_replanning_distance.xml` | 每 1 m 重规划，无恢复 | 是（模式 B） |
| `navigate_w_replanning_time.xml` | 1 Hz 定期重规划，无恢复 | 是 |
| `navigate_w_replanning_speed.xml` | 按速度比例重规划（`min_rate` 0.1、`max_rate` 1.0、`max_speed` 0.26） | 是 |
| `navigate_through_poses_w_replanning_and_recovery.xml` | 多点连续导航，配 `default_nav_through_poses_bt_xml` | 是 |
| `navigate_to_pose_w_replanning_goal_patience_and_recovery.xml` | 近目标时取消控制并等待障碍消失 | 否：用到 `CancelControl`、`PathLongerOnApproach`，未列入 `plugin_lib_names`，加载报 `Node not recognized` |
| `navigate_w_replanning_only_if_path_becomes_invalid.xml` | 路径失效才重规划 | 否：用到 `IsPathValid` 插件，未列入白名单 |
| `navigate_follow_record_path_w_replanning_and_recovery.xml`（及 `...1.xml`） | 记录路径跟随；树内**无** `ComputePathToPose`，`{path}` 由 `record_path` 话题提供 | 仅配 `default_follow_record_path_bt_xml` |

记录路径树的重要说明：把它设给 `default_nav_to_pose_bt_xml` 是错误的——`NavigateToPose` 的树必须自己产生 `{path}`，缺 `ComputePathToPose` 会让 `FollowPath` 拿不到路径而一直失败、反复恢复。记录路径模式应设另一个键，并与 `record_path` 话题、`navigate_follow_record_path` action 配合（属 S2-09 范围）：

```yaml
    default_follow_record_path_bt_xml: "$HOME/ros2_ws/install/nav2_bt_navigator/share/nav2_bt_navigator/behavior_trees/navigate_follow_record_path_w_replanning_and_recovery.xml"
```

## 八、运行验证

| 终端 | 角色 | 命令 |
|---|---|---|
| A | 整栈 | `ros2 launch yhs_nav2 yhs_nav2.launch.py` |
| B | 参数回读 | `ros2 param get /bt_navigator default_nav_to_pose_bt_xml` |
| C | 行为树日志 | `ros2 topic echo /behavior_tree_log --field event_log` |
| D | 目标下发 | `ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{...}" --feedback` |
| E | 速度残留检查 | `ros2 topic echo /cmd_vel` |

顺序：① CAN 起网 → ② 改 YAML → ③ 终端 A 启动 → ④ 终端 B 回读 → ⑤ RViz 给初始位姿 → ⑥ 终端 C 抓日志 → ⑦ 终端 D 下发同一目标。

判定标准：① 回读串与 YAML 完全一致，参数名为 `default_nav_to_pose_bt_xml`；② 模式 A 日志含 `RateController`/`ComputePathToPose`/`FollowPath`/`NavigateRecovery`，模式 B 含 `DistanceController` 且无 `NavigateRecovery`；③ 两模式对同一目标均 `SUCCEEDED`；④ 切换全程 `/cmd_vel` 无非零残留；⑤ 10 次切换无 `bt_navigator` 重启、无模式串用。

## 十、回滚与常见问题

```bash
cd ~/"ROS2 on YHS DT-mini Tutorial"
cp ~/yhs_labs/S1-07/backup/yhs_nav2.yaml.bak src/yhs_nav2/param/yhs_nav2.yaml
colcon build --symlink-install --packages-select yhs_nav2
source install/setup.bash
```

| 现象 | 原因 | 处理 |
|---|---|---|
| `[bt_navigator]: Couldn't open input XML file: navigate_w_replanning_and_recovery.xml` | 用了相对文件名或文件名不存在 | 用 `ros2 pkg prefix nav2_bt_navigator` 拼绝对路径，并 `ls` 确认文件存在 |
| `[bt_navigator]: Error loading XML file: ...` 且生命周期停在 `inactive` | 路径含空格但 YAML 未加引号，值被截断 | 值用双引号整体包裹 |
| `Exception when loading BT: ... Node not recognized: CancelControl`（或 `PathLongerOnApproach`、`IsPathValid`） | 该树用到未列入 `plugin_lib_names` 的插件 | 换白名单内的树（模式 A/B）；或在 `plugin_lib_names` 追加对应插件库后重编 `yhs_nav2` |
| 改了 YAML 但 `ros2 param get` 不变 | 只重启了部分节点，或当前终端未 `source` | 完整 `Ctrl+C` 停栈 → `source install/setup.bash` → 重新 `ros2 launch` |
| 远处目标直接失败，日志一直 `NavigateRecovery` 重试 | 树指到了记录路径树（无 `ComputePathToPose`），`{path}` 为空 | 改回模式 A 标准树；记录路径请用 `default_follow_record_path_bt_xml` |
| `ros2 param get /bt_navigator default_bt_xml_filename` 报 `Parameter not declared` | 旧参数名，Humble 已移除 | 正常现象，正是本实验要修正的缺陷 |
