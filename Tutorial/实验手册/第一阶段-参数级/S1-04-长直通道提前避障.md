## 2. 实验目标

1. 能说明局部代价地图的「陈旧时延」由 `update_frequency` 决定，「可见性时延」由 `publish_frequency` 决定，二者不可互相替代。
2. 修改后 `ros2 param get /local_costmap/local_costmap update_frequency` 回读 `10.0`，`publish_frequency` 回读 `5.0`。
3. `ros2 topic hz /local_costmap/costmap` 实测约 5 Hz（允许 ±1 Hz 抖动）。
4. 0.5 m/s 直行时对横穿锥桶的发现距离相对基线提升 ≥ 0.3 m。
5. 锥桶进入局部代价地图到 `/cmd_vel` 降至 0.1 m/s 的时间 ≤ 0.8 s，工控机 CPU 峰值 ≤ 70%。

## 5. 实施步骤

### 步骤 1：采集 5 Hz / 2 Hz 基线

- **操作说明**：参数不变，在长直通道以 0.5 m/s 直行，锥桶从侧方 2.5 m 处横向推入，记录「锥桶出现 → 代价图出现 → 开始减速 → 降至 0.1 m/s」四个时刻，取样 5 次。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && ros2 bag record -o "$HOME/yhs_labs/S1-04/result/baseline_run" /scan /local_costmap/costmap /cmd_vel /tf
```

- **预期输出示例**：`/local_costmap/costmap` 的 `average rate:` 约 2；回放中障碍出现在代价图上明显滞后于激光。
- **完成标志**：5 次取样四个时刻全部录入 `测试记录表.csv`。

### 步骤 2：提高刷新与发布频率并扩大窗口

- **操作说明**：编辑 `src/yhs_nav2/param/yhs_nav2.yaml`，定位 `local_costmap:` → `local_costmap:` → `ros__parameters:`（基线第 240~248 行），改两个频率与两个窗口尺寸。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && sed -n '240,248p' src/yhs_nav2/param/yhs_nav2.yaml
```

- **预期输出示例**：`update_frequency: 10.0`、`publish_frequency: 5.0`、`width: 8`、`height: 8`。
- **完成标志**：四项缩进均为 6 空格，层级在 `local_costmap` 的 `ros__parameters` 下（不是 `local_costmap_client`）；`width` 与 `height` 必须相等。

### 步骤 3：切到 0.5 m/s 速度档

- **操作说明**：本场景允许 0.5 m/s，需把 S1-01 的 0.2 档临时恢复为 0.5 档并同步制动上限。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS" && grep -n "max_vel_x:\|max_velocity\|max_decel" src/yhs_nav2/param/yhs_nav2.yaml
```

- **预期输出示例**：`max_vel_x: 0.5`、`max_velocity: [0.5, 0.0, 0.3]`、`max_decel: [-0.6, 0.0, -0.4]`。
- **完成标志**：与 6.3 节档位表一致，并在记录表标注「实验结束后恢复到 0.2 档」。

### 步骤 4：复测发现距离、减速时延与负载

- **操作说明**：重启生效后重复步骤 1 的取样方法（同一锥桶、同一推入速度、同一站位）共 5 次；随后以 0.5 m/s 连续运行 ≥ 2 h，每 15 min 采一次 CPU 与代价图频率。执行目录：`$WS`。
- **可复制命令**：

```bash
cd "$WS"
ros2 bag record -o "$HOME/yhs_labs/S1-04/result/after_run" /scan /local_costmap/costmap /cmd_vel /tf
ros2 topic hz /local_costmap/costmap
top -b -n 1 -p $(pgrep -f nav2_container) | tee -a "$HOME/yhs_labs/S1-04/result/cpu.log"
ros2 topic hz /local_costmap/costmap_updates | tee -a "$HOME/yhs_labs/S1-04/result/hz.log"
```

- **预期输出示例**：`average rate: 4.98` 附近；`%CPU` 峰值低于 70；`hz.log` 无掉到 0 的时段。
- **完成标志**：发现距离提升 ≥ 0.3 m；降至 0.1 m/s ≤ 0.8 s；`cpu.log` ≥ 8 条且全部 ≤ 70%。

## 6. 关键配置与代码

文件路径：`~/ros2_ws/src/yhs_nav2/param/yhs_nav2.yaml`

### 6.1 改动点 A：局部代价地图频率与窗口

替换位置：基线第 240~248 行整段（`local_costmap` → `local_costmap` → `ros__parameters`）。

```yaml
  local_costmap:
    ros__parameters:
      update_frequency: 10.0
      publish_frequency: 5.0
      global_frame: odom
      robot_base_frame: base_link
      use_sim_time: False
      rolling_window: true
      width: 8
      height: 8
```

| 参数 | 原值 | 新值 | 含义与影响 |
|---|---|---|---|
| `update_frequency` | 5.0 | 10.0 | 代价地图内部刷新频率（Hz）；0.5 m/s 下 5 Hz 每 0.2 m 才更新一次障碍位置，10 Hz 缩到 0.1 m |
| `publish_frequency` | 2.0 | 5.0 | 对外发布 `/local_costmap/costmap` 的频率；只影响可视与下游消费，不改变内部刷新 |
| `width` | 6 | 8 | 局部窗口宽度（m），车前前瞻由 3 m 增至 4 m |
| `height` | 6 | 8 | 局部窗口高度（m），必须与 `width` 相等 |
| `rolling_window` | true | true（保持） | 窗口跟随车体滚动，扩大窗口才有意义 |

### 6.2 刻意不改的部分

| 参数 | 现值 | 结论 |
|---|---|---|
| `resolution` | 0.05 | 保持。改小使栅格数平方增长，CPU 风险远大于精度收益 |
| `always_send_full_costmap` | True | 保持。频率提高后整图发布量上升，RViz 卡顿应先降可视化刷新 |
| `global_costmap.update_frequency` | 1.0 | 保持。本实验只优化局部层，全局层 1 Hz 足够 |

### 6.3 改动点 B：0.5 m/s 速度档（`FollowPath` 与 `velocity_smoother`）

```yaml
      max_vel_x: 0.5
```

```yaml
    max_velocity: [0.5, 0.0, 0.3]
    min_velocity: [-0.5, 0.0, -0.3]
    max_accel: [0.3, 0.0, 0.15]
    max_decel: [-0.6, 0.0, -0.4]
```

| 参数 | 0.2 m/s 档（混行区） | 0.5 m/s 档（本实验） | 说明 |
|---|---|---|---|
| `FollowPath.max_vel_x` | 0.2 | 0.5 | 本场景允许的线速度上限 |
| `velocity_smoother.max_velocity[0]` | 0.2 | 0.5 | 与 TEB 上限一致，避免平滑器成为隐形限速 |
| `velocity_smoother.max_accel[0]` | 0.15 | 0.3 | 0.5 m/s 加速时间约 1.7 s |
| `velocity_smoother.max_decel[0]` | -0.4 | -0.6 | 由验收「0.5→0.1 m/s ≤ 0.8 s」反推 `(0.5−0.1)/0.8 = 0.5`，取 0.6 留余量 |

> 该档为**长直通道专用**，实验结束必须回到 0.2 档，否则混行区安全约定被破坏。

### 6.4 窗口与检测距离的边界说明

- 窗口加大只扩大代价地图覆盖范围（车前 4 m），**不能越过障碍层量程**：局部 `obstacle_layer` 的 `scan`/`scan1` 未显式配置 `obstacle_max_range`，取 Nav2 默认 2.5 m（`raytrace_max_range` 默认 3.0 m）。
- 本实验收益主要来自两处：刷新时延减半、转向与贴边时窗口不再裁掉车前区域。若要进一步提升发现距离，需调整障碍层量程，属另一独立实验范围。
- 判定「发现距离提升 ≥ 0.3 m」以锥桶进入 `/local_costmap/costmap` 的车-桶纵向距离为准，不以激光原始量程为准。

## 10. 回滚与常见问题

### 10.1 回滚

执行目录：`$WS`。先恢复参数，再把速度档切回混行区设置。

```bash
cd "$WS"
cp -a "$HOME/yhs_labs/S1-04/backup/yhs_nav2.yaml.orig" src/yhs_nav2/param/yhs_nav2.yaml
colcon build --symlink-install --packages-select yhs_nav2
source install/setup.bash
```

预期输出：构建 `Summary: 1 package finished`；重启后 `update_frequency` 回读 `5.0`、`/local_costmap/costmap` 恢复约 2 Hz。若本次在 S1-01 之后进行，回滚会一并撤销 S1-01 的限速与平滑段，需按 S1-01 重新补回。

### 10.2 常见问题

| 报错文本 / 现象 | 原因 | 处理步骤 |
|---|---|---|
| `ros2 topic hz /local_costmap/costmap` 仍约 2 | 改到 `local_costmap_client`，或改在 `global_costmap` 段 | 确认层级为 `local_costmap:` → `local_costmap:` → `ros__parameters:`；回读 `publish_frequency` |
| `Parameter not set`（局部 `update_frequency`） | 局部代价地图未随控制器加载，或节点未 `active` | `ros2 lifecycle get /controller_server`；`ros2 node list` 中应有 `/local_costmap/local_costmap` |
| CPU 峰值超过 70% | 10 Hz 刷新 + 5 Hz 全量发布叠加，或同时跑建图 | 先把 `publish_frequency` 降到 4.0 复测；关闭多余 RViz 订阅；确认未并行跑 Cartographer |
| RViz 卡顿但 CPU 不高 | `always_send_full_costmap: True` 下整图发布带宽大 | 降低 RViz 刷新率或减少显示项，不要为此改代价地图参数 |
| `Failed to obtain robot pose` | TF 断链，常见于刚启动就发目标 | 等 `Managed nodes are active`；`ros2 run tf2_ros tf2_echo map base_link` 复核 |
| `teb_local_planner was not able to obtain a local plan for the current setting.` | 0.5 m/s 下窗口/前瞻不足，或障碍突然贴近 | 确认 `width`/`height` 已为 8；必要时评估 `max_global_plan_lookahead_dist` |
| 减速时延达标但最小间距不足 0.3 m | 起步距离太近，或 `min_obstacle_dist` 被前序实验改得过小 | 保持 `max_decel` 不变，回读 `FollowPath.min_obstacle_dist` |
| 实验结束忘记切回 0.2 档 | 档位为临时设置 | 按 10.1 节回滚，或在交付检查单增加「速度档位复核」一项 |
