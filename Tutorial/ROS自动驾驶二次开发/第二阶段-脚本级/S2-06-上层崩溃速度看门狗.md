## 2. 实验目标

1. 能说清速度链路：`controller_server → /cmd_vel_nav → velocity_smoother → /cmd_vel → yhs_can_control`，并指出**唯一**应当被监控的最终话题是 `/cmd_vel`。
2. 能编写 rclpy 节点，用 20 Hz 定时器检查"最近一次非零指令时刻"，超过 0.5 s 即向 `/cmd_vel` 发布零速 `Twist`。
3. 能解释为什么必须忽略零速帧：否则本节点自己发的零速会被当成"上游还活着"，形成自锁死循环。
4. 能完成 3 类故障注入（Ctrl+C 结束导航、`kill -9` 杀 `velocity_smoother`、急停后松开），实测停车时延 ≤ 0.5 s。
5. 能说明看门狗与 `velocity_smoother` 的 `velocity_timeout`（默认 1.0 s）的分层关系，并证明正常运行时不与上游抢指令。

## 5. 实施步骤

### 5.1 写入完整脚本

把下面全文写入 `~/yhs_labs/S2-06/cmd_watchdog.py`：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""S2-06 上层节点崩溃时的速度看门狗：/cmd_vel 超时即插入零速 Twist。"""

import time

import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy
from geometry_msgs.msg import Twist

RED, GRN, RST = '\033[31m', '\033[32m', '\033[0m'


class CmdWatchdog(Node):
    """PASSIVE：上游正常，不动话题；WATCHDOG：超时后持续发零速，直到上游恢复。"""

    def __init__(self):
        super().__init__('cmd_watchdog_s2_06')
        params = (('cmd_topic', '/cmd_vel'), ('timeout', 0.5), ('rate', 20.0),
                  ('zero_eps', 1e-4))
        for name, value in params:
            self.declare_parameter(name, value)
        self.topic = str(self.get_parameter('cmd_topic').value)
        self.timeout = float(self.get_parameter('timeout').value)
        self.rate = float(self.get_parameter('rate').value)
        self.eps = float(self.get_parameter('zero_eps').value)
        # 与 velocity_smoother / yhs_can_control 相同：RELIABLE + KEEP_LAST(1)
        qos = QoSProfile(depth=1, reliability=ReliabilityPolicy.RELIABLE,
                         history=HistoryPolicy.KEEP_LAST)
        self.pub = self.create_publisher(Twist, self.topic, qos)
        self.sub = self.create_subscription(Twist, self.topic, self.on_cmd, qos)
        self.zero = Twist()
        self.last_cmd = None          # 最近一次“非零”指令的接收时刻（单调秒）
        self.state = 'PASSIVE'
        self.trips = 0
        self.zero_sent = 0
        self.frames = 0
        self.create_timer(1.0 / self.rate, self.tick)
        self.get_logger().info(f'看门狗已启动：监控 {self.topic}，超时 {self.timeout:.2f} s，'
                               f'插入零速 {self.rate:.0f} Hz')

    def now_s(self):
        return self.get_clock().now().nanoseconds / 1e9

    def is_zero(self, msg):
        return (abs(msg.linear.x) < self.eps and abs(msg.linear.y) < self.eps
                and abs(msg.linear.z) < self.eps and abs(msg.angular.x) < self.eps
                and abs(msg.angular.y) < self.eps and abs(msg.angular.z) < self.eps)

    def on_cmd(self, msg):
        self.frames += 1
        if self.is_zero(msg):
            return      # 关键：零速不刷新计时，避免把本节点自己发的零速误判为“上游存活”
        self.last_cmd = self.now_s()
        if self.state == 'WATCHDOG':
            self.state = 'PASSIVE'
            print(GRN + '[恢复] 上游重新发出非零指令，看门狗交还控制权' + RST, flush=True)
            self.get_logger().info('上游恢复，停止插入零速')

    def tick(self):
        if self.last_cmd is None:
            return      # 尚未见到任何非零指令：不主动发零速，避免与启动阶段抢话题
        if self.now_s() - self.last_cmd > self.timeout:
            if self.state != 'WATCHDOG':
                self.state = 'WATCHDOG'
                self.trips += 1
                stale = self.now_s() - self.last_cmd
                print(RED + f'[看门狗] {stale:.2f} s 无新指令 → 插入零速（第 {self.trips} 次）'
                      + RST, flush=True)
                self.get_logger().error(f'上游中断 {stale:.2f} s，开始持续插入零速')
            self.pub.publish(self.zero)
            self.zero_sent += 1

    def shutdown(self):
        for _ in range(3):
            self.pub.publish(self.zero)
            time.sleep(0.05)
        self.get_logger().info(f'看门狗退出：收到 {self.frames} 帧，触发 {self.trips} 次，'
                               f'发送零速 {self.zero_sent} 帧')


def main(args=None):
    rclpy.init(args=args)
    node = CmdWatchdog()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.shutdown()
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### 5.3 故障注入（架空 → 落地）

1. 架空车轮，RViz 下发 3~5 m 目标，让 `/cmd_vel` 出现 0.2 m/s 左右的非零速度。
2. 打开终端 C 观察 `ros2 topic echo /cmd_vel`，按下表逐项注入故障，记录"最后非零帧 → 首个零速帧"的时间差。
3. 每类故障后重启导航，重新确认 `[恢复]` 行出现。

| 故障类型 | 注入方式 | 预期 |
|---|---|---|
| 上游被正常结束 | 在导航终端 `Ctrl+C` | 0.5 s 内出现 `[看门狗] ... 插入零速`，`/cmd_vel` 连续为 0 |
| 上游被强杀 | `pkill -9 -f velocity_smoother` | 同上；smoother 停止发布后，零速全部来自看门狗 |
| 急停后恢复 | 按急停 1 s 后松开 | 急停期间底盘已停；松开后若导航未重新发指令，看门狗继续补零 |

## 6. 关键代码与配置

| 代码段 | 作用 | 关键点 |
|---|---|---|
| `QoSProfile(depth=1, RELIABLE, KEEP_LAST)` | 与 `velocity_smoother`（`create_publisher(..., 1)`）和底盘订阅（depth 1）保持一致 | 用 `BEST_EFFORT` 会与底盘 RELIABLE 订阅**不兼容**，零速根本送不到 |
| `on_cmd` 中的零速过滤 | 只把非零帧视为"上游存活" | 否则自收自发形成"永远存活"的假象，看门狗永不触发 |
| `last_cmd is None` 直接返回 | 启动阶段不抢话题 | 导航尚未起来时不会凭空发零速 |
| `tick` 20 Hz | 超时后持续补零，而不是只发一帧 | 底盘按帧驱动，单帧零速可能被后续残余指令覆盖 |
| `state` 状态机 | 只在状态跳变时打印/告警 | 8 h 运行不刷屏，日志可读 |
| `shutdown` 补发 3 帧 | 退出瞬间防残留速度 | 3 × 50 ms 覆盖一个 CAN 发送周期 |

| 话题 | 类型 | 方向 | QoS | 说明 |
|---|---|---|---|---|
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 订阅 + 发布 | RELIABLE，depth 1 | 速度链路的**最终**汇聚点 |
| `/cmd_vel_nav` | `geometry_msgs/msg/Twist` | 不订阅 | — | TEB 原始输出，尚未平滑；监控它会漏掉 smoother 崩溃 |

| 参数 | 默认 | 说明 |
|---|---|---|
| `cmd_topic` | `/cmd_vel` | 监控与补零的同一话题 |
| `timeout` | 0.5 | 超时阈值（s），可配 0.2~2.0 |
| `rate` | 20.0 | 补零频率（Hz），与 smoother 输出同频，便于等间隔覆盖 |
| `zero_eps` | 1e-4 | 判定"零速"的阈值（m/s、rad/s），防止 1e-9 噪声被当作有效指令 |

**与 `velocity_smoother` 的关系（避免指令抢占）**：`velocity_smoother` 自带 `velocity_timeout`（默认 1.0 s），超时后**只发一帧**零速并置 `stopped_`；`behavior_server` 的旋转/后退恢复也直接发布 `/cmd_vel`，周期约 10 Hz。看门狗的 0.5 s 阈值比 smoother 更早，是更外层的一道兜底；三者发出的零值语义一致，不会互相"顶"。真正需要避免的是看门狗在正常运行时插话——本实现只在"超过 0.5 s 没有任何非零帧"时才发布，并在收到新非零帧的同一次回调里立刻回到 `PASSIVE`；恢复行为的 10 Hz 指令同样会刷新计时，因此恢复期间不会误触发。正常导航期间 `cmd_watchdog` 对 `/cmd_vel` 的贡献为 0 帧。

## 10. 回滚与常见问题

回滚：①在终端 B `Ctrl+C`，脚本补发 3 帧零速后退出；②`rm -rf ~/yhs_labs/S2-06`；③确认 `git status` 无新增；④本实验不改任何仓库文件与 Nav2 参数，`velocity_smoother` 配置保持原样，无需还原。

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即报 `[看门狗] 0.50 s 无新指令` | 运行前已有历史非零帧被收到 | 重启导航后重新运行脚本；或确认当时确实无上游 |
| 故障注入后车仍在动 | 零速发到了 `cmd_vel_nav` 或被命名空间隔离 | `ros2 topic info /cmd_vel -v` 核对；确认脚本未加 `--ros-args -r __ns:=...` |
| 正常行驶时偶发告警 | `timeout` 设得过小，或 smoother 掉帧 | 恢复 0.5 s；`ros2 topic hz /cmd_vel` 看是否低于 15 Hz |
| 底盘收不到零速 | QoS 不兼容 | 保持 `RELIABLE` + `KEEP_LAST(1)`，不要改成 `BEST_EFFORT` |
| 与 `velocity_smoother` 都发零速、底盘抖动 | 上游仍在发非零、看门狗误判超时 | 检查系统负载与 DDS 丢包；必要时把 `timeout` 调到 0.8 s |
| `ModuleNotFoundError: No module named 'rclpy'` | 未 source ROS 2 | `source /opt/ros/humble/setup.bash`，使用 `/usr/bin/python3` |
| 落地测试车冲出去 | 未架空即注入故障，且 `timeout` 过大 | 立即按硬件急停；恢复架空流程，先小速度验证 |
